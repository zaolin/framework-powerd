# Security

The daemon's HTTP API is a **control plane**, not just a status endpoint. It can
change power profiles and send `SIGSTOP`/`SIGCONT` to game process trees. Treat
it accordingly.

## Authentication

- `server.jwt_secret` (or `--jwt-secret` / `JWT_SECRET`) enables HMAC-SHA256 JWT
  Bearer authentication.
- Tokens must include `"authorized": true`. A token without that claim is
  rejected even if the signature is valid.
- Tokens generated by `framework-powerd token` expire after one year.
- Non-Bearer `Authorization` schemes are rejected.
- If no secret is configured, the daemon refuses to start unless
  `--disable-auth` is explicitly passed.

### Generate a token

```bash
export TOKEN=$(framework-powerd token --jwt-secret="$(cat /etc/framework-powerd/jwt-secret)")
```

Prefer `server.jwt_secret` in the config file or the `JWT_SECRET` environment
variable over `--jwt-secret`: command-line arguments are visible in the process
list.

## Network exposure

- Default bind address is `localhost`.
- To expose the daemon on a LAN, set `server.address` to `0.0.0.0` **and** use a
  firewall. Ideally restrict the port to the Home Assistant host.
- `/healthz` is unauthenticated by design. It exposes version, uptime, idle
  state, memory percentage, monitor booleans and the metrics file path/status.
  It does not expose the JWT secret or control-plane actions.
- All other endpoints require auth.

## `--disable-auth`

`--disable-auth` is an escape hatch for local development. It logs a warning and
leaves the control plane open. Only use it with `server.address=localhost`.

## Rate limiting

`POST /mode` and `POST /activity` are limited to 1 request/second with a burst
of 5 per client IP. The limiter keys on the IP, not the TCP source port, so
opening new connections does not bypass it. Idle buckets are pruned.

## systemd hardening

The shipped unit uses:

- `User=root` — required for `/dev/input`, `/sys` tunables and
  `powerprofilesctl`.
- `NoNewPrivileges=yes`
- `PrivateTmp=yes`
- `ProtectHome=yes`
- `ProtectSystem=full`
- `ProtectKernelModules=yes`
- `ProtectKernelLogs=yes`
- `ProtectControlGroups=yes`
- `ProtectKernelTunables=no` — **must stay off**, the daemon writes PCIe ASPM,
  EPP and CPU governor tunables under `/sys`.
- `RestrictSUIDSGID=yes`, `RestrictRealtime=yes`, `LockPersonality=yes`
- `RestrictAddressFamilies=AF_UNIX AF_INET AF_INET6 AF_NETLINK`

`Type=notify` plus `WatchdogSec=30s` lets systemd detect a hung daemon and
restart it.

## Data at rest

- `metrics.json` contains only energy counters and timestamps. It contains no
  credentials.
- The JWT secret lives in the config file or environment. Restrict permissions
  on the config file (`chmod 600` if it contains a secret).
- Home Assistant diagnostics redact `token`, `jwt_secret`, `password`, `secret`
  and `authorization` fields.

## Recommendations

1. Run the API on localhost and put Home Assistant on the same host, or firewall
   the port to the HA host only.
2. Use a dedicated random JWT secret, not a password.
3. Rotate the token if it leaks; changing the secret invalidates all tokens.
4. Keep the daemon and Home Assistant updated.
5. Review the systemd unit after upgrades; hardening options are part of the
   security boundary.
